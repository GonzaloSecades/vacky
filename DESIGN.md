## Overview

Vacky should read as one travel product, not as two disconnected themes awkwardly stitched together. The product spans reflective memories from past trips and forward-looking planning for future ones, so the visual system has to hold nostalgia and anticipation in the same frame without breaking coherence.

Memory-facing moments should feel intimate, tactile, slightly romantic, and editorial. Planning-facing moments should feel fresh, optimistic, scan-friendly, and operationally clear. The connective tissue is photography-first storytelling on calm light surfaces, with ornament used as a supporting cue rather than the main event.

Twilight Postcards replaces the earlier coral-heavy, Airbnb-adjacent direction with a lighter, more atmospheric palette centered on plum. Plum carries the brand accent, memory accents lean mauve, planning accents lean transit blue, neutral paper surfaces stay soft and quiet, and the darkest contrast is reserved for dense utility needs such as itinerary controls and map overlays.

Dashboard and memory-led surfaces may run slightly warmer and more decorative. Trip overview surfaces should bridge memory and planning. Itinerary, planner, and map-heavy surfaces should stay cleaner, tighter, and higher-contrast so the product remains fast to read when the task becomes logistical.

## Colors

Palette 8 is the foundation. The primitive layer is explicit and stable: `#7B5EA7` plum-brand, `#684D92` twilight-hover, `#F4F0FB` lavender-entry, `#FBF9FE` evening-backdrop, `#FFFFFF` story-paper, `#EEE8F7` ticket-lilac, `#DDD5EA` fold-border, `#251F31` midnight-journal, `#756C86` margin-muse, `#4E8A73` booking-success, `#5688D4` tram-line-blue, `#C48AA8` vintage-mauve, and `#E3C46D` lantern-gold. The semantic layer then maps those primitives to implementation roles so later UI work can stay consistent without duplicating raw values.

Use the color system in four clearly separated jobs. Memory-facing accents use `accent-memory` for reflective, personal, or souvenir-like cues. Planning-facing accents use `accent-planning` for itinerary logic, navigation hints, and future-trip emphasis. Calm neutral surfaces use `surface-page`, `surface-panel`, `surface-subtle`, and `surface-ticket` to preserve a paper-led light mode. Dense utility contrast uses `utility-strong` and `text-strong` when map controls, planner chrome, or dense metadata need unmistakable legibility.

`accent-primary` is the branded interaction driver. It belongs on primary actions, selected high-value calls to action, and a small number of editorial emphasis moments. It should not compete with every secondary affordance on a screen. `accent-primary-hover` deepens that same role rather than introducing a new color story.

Placement matters more than quantity. Dashboard and memory-led views can tolerate a little more lavender and lilac warmth, plus the occasional mauve or gold accent around editorial details. Trip overview surfaces should mix memory warmth with planning clarity in a balanced way. Planner, itinerary, and map-heavy views should lean harder on white, near-white, soft lilac, and midnight-journal contrast, keeping mauve and gold nearly absent unless they are intentionally commemorative.

Restraint is part of the system. Avoid multicolor layouts, rainbow decorative clusters, or large mauve and gold fills that overpower photography. Warm highlights and memory accents should punctuate, not flood. Example usage: a hero CTA in plum, a selected itinerary affordance in transit blue, a saved memory marker in vintage mauve, paper cards on white or lilac, and map controls in midnight-journal for maximum clarity.

## Typography

The default pairing is Manrope plus DM Serif Display. Manrope handles body copy, labels, dense utility text, metadata, and product UI because it stays calm and legible across scan-heavy trip planning surfaces. DM Serif Display introduces the reflective, travel-editorial note needed for hero headlines, section-leading moments, and occasional memory-first storytelling without turning the whole product into a magazine pastiche.

This pairing fits Vacky's emotional duality better than a single-family system. Memories need a touch of romance and printed-travel nostalgia; planning surfaces need disciplined utility. Manrope carries the operational side cleanly, while DM Serif Display gives the product a sense of authorship when the UI needs to feel like a postcard, journal spread, or trip title page.

Inter plus Playfair Display is an approved fallback pairing when implementation safety matters more than distinctiveness. It is dependable and easier to find in many ecosystems, but it reads more generic and less specific to Vacky's voice. Satoshi plus Crimson Pro is exploration-only in this repo: the pairing is appealing, but Satoshi introduces sourcing and self-hosting risk here, whereas Manrope and DM Serif Display are realistic through `next/font/google`.

Existing `Geist_Mono` may remain as a utility mono fallback for codes, coordinates, or technical snippets, but it should stay subordinate to the main pair. Typography should generally keep decorative display moments rare, labels disciplined, and body text relaxed enough to support both itinerary scanning and longer-form reflection.

## Layout

Vacky should use one editorial-utility layout model rather than separate visual systems. Memory-led surfaces get more breathing room, larger image-led composition, and a little more asymmetry or atmospheric whitespace. Planner and map-heavy surfaces keep tighter alignment, stronger edge definition, and faster scan behavior. Trip overview surfaces sit in the middle, using a balanced composition that can show story and logistics together.

The spacing rhythm remains the existing 8px cadence already visible in the app, with a 4px half-step for finer alignment. Sections should breathe, but they should not drift into loose lifestyle-land on surfaces that are trying to help a user book, organize, or navigate. Use gutters and section spacing to preserve composure, then compress inside utility zones where comparison, sequencing, and wayfinding matter more than mood.

## Elevation & Depth

Depth should feel like layered paper and printed matter, not floating SaaS glass. Most hierarchy should come from tonal steps between `surface-page`, `surface-panel`, `surface-subtle`, and `surface-ticket`, supported by soft borders and quiet shadows. The effect should suggest stacked documents, tucked tickets, and lifted postcards rather than glossy cards hovering over a void.

Borders do a large share of the work. `border-soft` should define folds, seams, card edges, and segmented controls before shadow becomes necessary. Shadows stay restrained and broad, mainly to separate important panels from the page or to help image-led cards feel tactile. Dashboard and memory-led surfaces can accept slightly richer layering, but still within a gentle paper stack hierarchy.

Stronger contrast belongs where utility needs it. Planner chrome, itinerary containers, and map controls can use firmer tonal separation and darker contrast so scanning remains fast under operational load. Even there, depth should remain calm and controlled rather than dramatic or glossy.

## Shapes

The shape language is softened paper rather than novelty geometry. Cards and hero panels should use gentler radii that feel like premium printed pieces with rounded corners, while dense controls tighten slightly to preserve crispness and scan speed. Pills are allowed for segmented controls, compact actions, and micro-labels, but they should stay restrained and never become the defining silhouette of every surface.

Think in terms of postcards, tickets, margin tabs, and editorial panels. That means softened rectangles, long rounded strips, and occasional circular or oval stamp moments used as accents. It does not mean novelty cutouts, exaggerated scallops, loud die-cut effects, or decorative shapes that compete with content.

Planner-adjacent surfaces should stay more disciplined than memory-led ones. Trip cards and hero panels can feel slightly softer and more inviting. Itinerary panels, data-heavy cards, and map controls should use tighter radii so the interface feels reliable under pressure.

## Components

Palette 8 adoption should be visible in purpose, not just in token names. Plum is the primary branded interaction color. Mauve belongs to memory cues, not generic button states. Transit blue belongs to planning and wayfinding, not broad decorative fills. Paper whites and lilacs carry the page. Midnight-journal is the high-contrast utility anchor. If a component cannot justify why it needs one of the accent colors, it should probably sit on a neutral surface instead.

Decorative travel drawings are allowed, but they must stay subordinate to photography and task clarity. Quiet route lines, contour lines, compass ticks, postal marks, destination line drawings, or corner ornaments belong at hero edges, footer bands, empty-state atmospheres, or selected memory-led supporting panels. They do not belong inside dense planner controls, map overlays, form fields, or list-heavy itinerary rows. Density should remain low enough that removing the drawings would not change the information architecture.

Destination-aware postage stamps are memory reinforcers, not badges. They may appear as small surface accents on selected trip cards, memory-led hero areas, journal-like recaps, or other commemorative contexts tied to place. They should stay subtle in scale, avoid blocking or tinting photography, and never stack into a collage. They are not status chips, not CTA containers, and not a generic decoration repeated on every card.

Primary button: use plum fill with light text and a confident, warm presence. It should feel decisive and premium, never coral-like, hot, or sporty. Hover states deepen into twilight-hover rather than shifting hue families.

Secondary button: use paper or ticket-lilac surfaces with soft borders implied through context, plus strong text contrast. It should feel tactile and supportive, not washed out. This is the default companion action on editorial and utility surfaces alike.

Trip card: keep photography dominant. The card should frame image, destination, and trip identity first, with metadata secondary. Optional stamp or corner ornament treatment is acceptable only on select states, and only at low density.

Hero panel: treat it as the editorial lead surface. It may carry light illustration at the edges and a little more warmth than planner chrome, but photography still wins. The panel should feel like the opening spread of a journey, not a decorative poster.

Metadata card: use a paper card with quiet travel cues and high label-to-data clarity. This is where typography discipline matters more than ornament. Small cues are enough.

Segmented tabs: make them ticket-like and calm in the inactive state, with a crisp active state that feels tucked into a paper control. They should stay readable and premium without becoming soft blobs.

Itinerary and planner panel: keep it cleaner and tighter than memory-led surfaces. Ornament is minimal, alignment is stricter, and scan speed takes priority over atmosphere. This is one of the main places where utility contrast earns its weight.

Map controls: use the darkest contrast in the system. Controls should be compact, legible, and obviously interactive over both maps and photos. They may feel denser and firmer than the rest of the UI, but they still belong to the same product.

Stamp motif: keep it small, destination-aware, and memory-forward. It should reinforce place and recollection without reading as a badge, sticker, or collectible UI gimmick.

Decorative illustration layer: keep the set to route lines, contour lines, compass marks, small travel icons, postal marks, destination line drawings, corner ornaments, and quiet footer or header accents. Illustration supports the page perimeter and selected memory moments; it should not occupy the center of task-heavy layouts.

Section kicker and micro-label: use as travel-editorial utility labels with discipline. They can introduce sections, annotate memory moments, or structure overview pages, but overuse will make the product feel busy and precious.

Footer treatment: allow the footer band to become slightly warmer and more atmospheric than the rest of the page. Illustration can appear more freely there than in planner chrome, but it still should not outweigh calls to action or essential navigation.

Surface guidance is explicit. Dashboard and memory-led surfaces can carry slightly more warmth and ornament. Trip overview surfaces should bridge memory and planning with balanced restraint. Itinerary, planning, and map-heavy surfaces must stay cleaner, faster, and higher-contrast.

## Do's and Don'ts

- Do keep photography as the first-class storytelling layer and let ornament remain secondary.
- Do use plum as the branded interaction accent and reserve mauve and transit blue for their distinct semantic roles.
- Do keep memory surfaces slightly warmer and more atmospheric than planning surfaces without splitting the product into separate themes.
- Do make planner and map-heavy views cleaner, tighter, and more contrast-driven than dashboard or recap views.
- Do inspect representative existing primitives before proposing later UI implementation work.
- Don't drift back toward coral, Airbnb-adjacent warmth, or a generic vacation-rental palette.
- Don't introduce dark-mode guidance, multi-theme branching, or token sprawl in this document.
- Don't let stamps, route drawings, or decorative cues compete with photography, metadata clarity, or planner speed.
- Don't use mauve, gold, or illustration as broad fill treatments across operational screens.
- Don't invent page-by-page redesign rules here; this file is the light-mode system source of truth, not an implementation checklist.
